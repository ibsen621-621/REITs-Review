# REITs 申报材料智能质控（QC）复核 · Gemini Gem 部署包

把一位"头部券商资深投行内核 / 质控负责人"装进一个可直接部署的 **Google Gemini Gem**，对基础设施公募 REITs / 持有型不动产 ABS 的申报材料做显微镜级"排雷"复核，并输出可落地修改的《质控复核报告》。

> ⚠️ 本仓库内容为投行 QC 辅助工具，**不构成任何法律、财务或投资意见**；正式报送前务必由项目组与外部律师、会计师按最新《指引》及交易所审核口径二次复核。文中 70% / 90% / 20% / 战略配售锁定期等阈值按 2024–2025 现行口径标注，规则更新较快，请以最新官方口径为准。

## 一、目录结构

```
REITs-Review/
├── README.md                              ← 本文件：部署指南
└── gemini-gem/
    ├── instructions.md                    ← 【核心】粘贴进 Gem「指令 / Instructions」框
    └── knowledge/                         ← 上传为 Gem「知识 / Knowledge」文件（共 4 个）
        ├── 01-基础数据与业务逻辑核查清单.md
        ├── 02-资产类型专项清单.md
        ├── 03-监管依据与红线阈值.md
        └── 04-报告模板与话术重构库.md
```

设计思路：**指令框放"操作系统"（角色、原则、流程、调用规则），知识库放"检查清单与参照系"**。这样既能压住指令框长度，又能让复核逻辑可维护、可迭代。

## 二、5 分钟部署到 Gemini Gem

1. 打开 **[gemini.google.com](https://gemini.google.com)** → 左侧 **Gems** → **新建 Gem（New Gem）**。
2. **名称**：填 `REITs 质控复核官`（或自定义）。
3. **指令（Instructions）**：打开 [`gemini-gem/instructions.md`](gemini-gem/instructions.md)，**全文复制**粘贴进指令框。
4. **知识（Knowledge）**：点击「上传文件」，把 `gemini-gem/knowledge/` 下的 **4 个 `.md` 文件全部上传**。
   - 如平台不接受 `.md`，将其内容另存为 `.txt` 或 `.pdf` 再上传即可（内容不变）。
5. 点击 **预览 / Preview** 自测：粘贴一段招募书 / 评估报告节选，确认它会按"模块 A→B→C + 表格化报告 + 待补材料清单"输出。
6. **保存 / Save**。完成。

> 使用时：把待复核文档（或节选）粘贴 / 上传给该 Gem 即可。长文档支持分章节、分批投喂，最后让它汇总。

## 三、它会做什么

| 模块 | 作用 | 对应知识文件 |
|---|---|---|
| **A 硬伤排雷** | 占位符、域代码残留、数据打架、单位串档、主体张冠李戴、证照过期 | 01 |
| **B 业务逻辑** | 权属/CoC/共用资产/关联交易、70% 稳健性、EBITDA 调节桥、回收资金合规、杠杆与战配 | 01 + 02 + 03 |
| **C 表述润色** | 规避内控一票否决敏感词、风险闭环重构、去模糊指代、去 AI 味、定量替代定性 | 04 |
| **输出** | 结构化《质控复核报告》表格 + 严重性分级（🔴🟠🟡🔵）+ 待补材料 checklist | 04 |

## 四、维护与升级

- **更新监管口径**：只改 `03-监管依据与红线阈值.md`，重新上传覆盖即可，无需动指令框。
- **新增资产类型**：在 `02-资产类型专项清单.md` 追加一节后重新上传。
- **调输出体例**：改 `04-报告模板与话术重构库.md`。
- **平台迁移**：本指令同样适配 OpenAI GPTs（指令→System、知识→Knowledge）、Claude Projects / Agent Skills（可改写为带 frontmatter 的 `SKILL.md` + 分文件）。

## 五、已知限制提示

- Gemini Gem 的指令框与知识库共享上下文窗口；免费档上下文较小，**Pro / Ultra 档**（更大上下文）体验更佳。
- 知识文件建议保持精简、结构化（标题 + 清单），便于模型检索命中。
- 该 Gem 仅做**辅助质控**，不替代内核会、外部中介与监管审核。
